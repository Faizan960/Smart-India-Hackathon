# AWS Sentinel - Laya Base

This directory is an isolated prototype layer for adding Laya as the primary learned fault decision model.

## Safety boundary

Nothing in the current production path imports this package.

- api/inference.py is unchanged.
- ml/inference.py is unchanged.
- ml/classifier.py is unchanged.
- requirements.txt is unchanged.
- No HTTP route is added.
- Existing Isolation Forest behavior is unchanged.

## Intended architecture

AWS telemetry -> state preparation -> fine-tuned Laya -> potential fault -> existing Isolation Forest verification -> final deterministic status.

The implementation does not average Laya and Isolation Forest scores. Laya produces a typed decision; Isolation Forest independently verifies whether the observation is statistically anomalous.

## Dataset strategy

The dataset builder expects healthy telemetry, ideally from real AWS/IMD observations. It creates controlled fault-injected variants for supervised fine-tuning.

The labels are generated by the controlled injection process; they are not claimed to be native IMD fault labels.

Supported labels:

- NORMAL
- SENSOR_DROPOUT
- TEMPERATURE_SPIKE
- TEMPERATURE_DROP
- SENSOR_FREEZE
- SENSOR_DRIFT
- PRESSURE_SPIKE
- PRESSURE_DROP
- HUMIDITY_SPIKE
- HUMIDITY_DROP
- UNKNOWN_ANOMALY

## Prepare training data

From the repository root:

    python -m ml.laya_base.train_prepare --input data/imd_aws_healthy.csv --output ml/laya_base/data/aws_fault_train.jsonl

The CSV must contain:

    timestamp,temperature,humidity,pressure,wind_speed

## Manual runtime test

After installing the optional dependencies and obtaining a trained checkpoint:

    from ml.laya_base.decision import LayaDecisionEngine

    engine = LayaDecisionEngine()
    decision = engine.predict(history_df)

    print(decision.decision)
    print(decision.confidence)

To verify against the existing Isolation Forest:

    from ml.inference import predict_anomaly
    from ml.laya_base.verification import verify_laya_decision

    anomaly = predict_anomaly(history_df)
    result = verify_laya_decision(history_df, engine, anomaly)
    print(result)

## Fine-tuning

dataset.py outputs the same high-level state/questions/gold structure used by Laya's typed-decision fine-tuning workflow.

The next step is GPU fine-tuning: convert these records into Laya build_sequence(...) items, fine-tune the checkpoint, evaluate on a held-out telemetry set, then load the resulting checkpoint with decision.py.

Do not add Laya dependencies to the production deployment until the training and runtime path has been validated.
