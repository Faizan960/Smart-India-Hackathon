The hybrid detection engine — three independent lenses

Each detector looks at the stream differently, so we can point at exactly which signal triggered an alert instead of handing back an opaque anomaly score.

1

Statistical detector

Rolling z-score against a 2-hour trailing window per sensor. A reading that's more than 4 standard deviations from its own recent baseline gets flagged.

Catches sudden spikes
2

Temporal drift detector

Compares a short-term rolling mean against a long-term baseline mean. A slow, gradual divergence between the two — invisible to a single-point check — signals miscalibration.

Catches gradual drift
3

Multivariate consistency

Uses a physical prior — humidity should move roughly opposite to temperature deviation. A large residual from that expected relationship means the sensors disagree with physics, even if each looks "in range" alone.

Catches cross-sensor faults no single sensor shows

Fusion, health scoring, and explainability

Structural faults (missing data, frozen values, out-of-range readings) resolve deterministically with high confidence. Behavioral faults get a confidence score based on how many of the three detectors agree — and every alert is paired with a plain-English reason, not just a number, because a judge should be able to read why in one glance. A rolling 4-hour health score then tracks each station's overall trust level over time, catching slow degradation even before any single alert fires.

What we actually used to build this

No black-box ML library doing the heavy lifting — the detection logic is transparent, tunable, and explainable end to end. Here's the real stack, layer by layer.

Data layer

Synthetic AWS stream generator

  • Python + NumPy for a diurnal (day/night) temperature cycle, slow-drifting pressure, and anti-correlated humidity
  • Pandas for the timestamped, multi-station DataFrame
  • Five labeled fault types injected on top: spike, freeze, drift, dropout, cross-sensor inconsistency — each with ground-truth labels for scoring
Why: lets us measure real precision/recall before any sponsor data is available, and swaps for real IMD/MoES data without changing the pipeline interface.
Detection layer

Hybrid rule + statistics engine

  • Rolling-window statistics in Pandas (z-score, short/long mean divergence)
  • A simple physics-based residual check for cross-sensor consistency
  • No opaque deep model — every threshold is a number we can defend to a judge
Why: explainability is a scored rubric criterion — a hand-tunable ensemble is easier to justify live than a neural net.
Fusion layer

Classification + explanation

  • Python rule-based fusion combining quality flags + detector votes
  • Outputs type, severity, confidence, and a generated plain-English reason per row
  • Evaluation harness scores everything against injected ground truth (precision/recall/F1/false-alert rate)
Why: keeps "what happened" and "how confident are we" as separate, auditable numbers.
Presentation layer

This dashboard

  • Single-file HTML/CSS/vanilla JavaScript — no build step, runs offline from any laptop
  • Chart.js (CDN) for the live-updating sensor chart
  • Pipeline output exported to JSON once, then replayed client-side at adjustable speed for the demo
Why: zero setup risk on stage — no server, no dependencies to install, just open the file.

How we evaluated it

1

Generate with known answers. Every synthetic reading carries a ground-truth label (normal or a specific fault type) set at injection time.

2

Run detection blind. The pipeline never sees the ground-truth labels — it only sees raw sensor values, exactly like it would with real station data.

3

Score point-by-point. Every reading is compared prediction vs. truth to get precision, recall, F1, and false-alert rate — plus a per-fault-type recall breakdown.

4

Report it as-is. No cherry-picking the best run or hiding the weak category — the drift number below is the real number.

Known limitation

Drift detection sits at ~25% recall — gradual sensor bias looks a lot like normal diurnal variation with our current short-vs-long rolling mean approach. A CUSUM-style test is the planned fix, and we're flagging it here rather than hiding it.
